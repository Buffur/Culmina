## Delegation constraints

- Give a CLI worker a self-contained task, relevant source paths, allowed files, acceptance criteria and an explicit report format. Split independent work only when it reduces cost or uncertainty.
- When restricting Claude's tools, include `Skill` if the task requires plugin skill invocation. Include its agent delegation tool only if nested delegation is intended. A worker restricted to Read/Edit/Grep cannot be assumed to have invoked skills or delegated work.
- Treat installed plugin instructions as task aids. User instructions, repository decisions and frozen scope take precedence. In particular, the Flutter plugin's Riverpod 3.x, typed-result and migration prescriptions are not permission to migrate the existing app.
- Use fully qualified skill names when names overlap. Avoid stacking full-audit, Superpowers reviews and Engineering reviews on the same trivial change.
- Audit Suite frontend/backend lenses explicitly assume React/Zustand/Tailwind and Tauri/Rust respectively. Do not apply these stack-specific prescriptions to the plain browser prototype or native Flutter implementation. Inspect even UX/accessibility lenses for product assumptions before using them.
- Superpowers injects a session-start hook; Task Observer asks to activate before tools and persist observations. Give bounded workers explicit no-observation/no-memory-write constraints when only read-only work is authorized. Their self-activation wording does not override owner instructions.
- Do not automatically commit, merge, publish, install plugins, modify permissions or run destructive migration/golden workflows from a generic plugin checklist.
- Re-read the selected skill before applying it. This inventory alone does not activate every listed skill.
