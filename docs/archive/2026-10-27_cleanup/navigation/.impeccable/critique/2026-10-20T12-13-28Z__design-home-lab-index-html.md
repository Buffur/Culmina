# Hybrid: application-wide design review — 2026-10-20

Method: two independent assessments (`/root/hybrid_design_review` and `/root/hybrid_browser_evidence`), followed by parent source verification and bounded Claude CLI / AntiGravity CLI checks. Assessment A finished before detector findings entered the synthesis. The first attempts were interrupted by usage limits; work resumed from saved evidence, without repeating completed suites.

**Status: analysis and proposals only.** The owner asked to inspect all pages and suggest improvements across the app, working only on the original Hybrid (`variant=blend`). No application, CSS, configuration, skill or memory was changed. This report is not a native-roadmap amendment, implementation authorization or production acceptance.

## Verdict

Keep Hybrid Notion + Journal: an open planning notebook, restrained surfaces, a functional Manrope voice and selective serif night heading. The biggest improvement is to make each existing screen reveal its answer and next action sooner. More variants, colours, cards, statistics or product modules would dilute this pass.

Strengths to preserve:

1. Fit, persistence and observed result are distinct; explicit units and Unknown protect scientific meaning.
2. The shared night rail, Moon lanes and selected-night context belong to this product rather than a generic dashboard.
3. Scoped Apply/Save/Cancel, immutable historical snapshots, inline validation and checked restore already provide useful control.

## Cognitive load and user journey

Load is moderate overall, with dense pockets in equipment creation, full snapshots and condition interpretation. The useful pattern is already present: explicit context, grouped inputs, scoped action and reachable detail. The weak pattern is repeated limitation/help paragraphs competing with the next control.

- First-time planner: may read too much before acting, especially Add rig and Planning preferences. Keep explanation attached to the decision it supports.
- Returning field user: repeated legends and weakly differentiated secondary text slow scanning. Improve hierarchy without shrinking type or weakening the documented red field theme.
- Keyboard / enlarged-text user: the date-focus defect and increased scrolling make stable focus, concise leads and clear headings especially consequential. Native screen-reader/IME/gesture behaviour remains unverified.

Six target results, five camera classes and a calendar are legitimate domain selections, not defects just because more than four options are visible. Search, grouping and readable adaptation should reduce effort without deleting meaningful choices.

The opening is reassuring (fit and a clear planner action); the valley is reading long forms/snapshots; the ending should always state whether the user applied a draft, saved a plan or recorded a result.

## Application-wide ideas without expanding the product

These are separate **follow-up proposals**, not extra items silently added to the five-priority pass:

1. **Close the prototype's continuity gaps:** later make Library-managed example records usable by the existing Plan pickers, and demonstrate the existing Settings → current Plan budget/fit relationship. Current `plan.js` uses fixed `rigs`; Library has separate storage; Settings explicitly does not recalculate Plan. These are documented prototype limits, not proven Flutter bugs. Preserve management versus explicit selection, saved snapshots and global versus plan-specific scope. The native `SettingsScreen.scopeNotice` is the functional reference.
2. **Carry context and return position consistently:** selected site/night, current tab, list query and scroll position should survive appropriate returns, matching the existing native stateful shell intent. Browsing still must not mutate a saved plan.
3. **Complete representations of existing native flows only when requested:** Welcome, metadata confirmation, GPS/map site picking, session sharing/export and full application backup already belong to the source product. Their absent/limited Hybrid representation is not a reason to invent new modules or simulate success.

Retain compact Home Weather, the existing night ramp, one Hybrid visual direction and the current scientific contracts. Do not add streaks, dashboards, goals, black-box scores, camera controls, new font/palette comparisons or cloud/account features to this review's scope.
