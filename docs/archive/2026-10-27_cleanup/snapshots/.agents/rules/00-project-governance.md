# Project governance rules

Status: active supplemental guidance, reconciled 2026-10-24. The shared contract is [AGENTS](../../AGENTS.md), the sole current state is [PROGRESS](../../docs/refinement/PROGRESS.md), operational procedure is [AI_WORKFLOW](../../docs/AI_WORKFLOW.md), and verification is [VERIFICATION_POLICY](../../docs/VERIFICATION_POLICY.md).

- The owner's current bounded task governs execution. Approved F/G/S criteria are contracts, not an automatically active queue.
- An explicitly supplied implementation task authorizes its complete in-scope cycle, including multi-file/cross-layer work. Do not request duplicate approval for ordinary implementation choices.
- New unresolved decisions or material scope expansion need their relevant owner gate; continue independent authorized work where possible.
- Research, planning, reassessment and validation do not silently become application implementation. A completed task does not start another unless the current owner request names the finite group and stop conditions.
- Verify dated findings and memory against current sources. Separate observed implementation, approved intent, reused evidence and owner acceptance. Preserve private data and other writers' work.
- Read rules/skills selectively; their presence is not proof of automatic loading in every client.
