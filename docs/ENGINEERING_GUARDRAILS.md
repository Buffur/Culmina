## Commands and persistence contracts

- Local full gate: `dart run tool/check.dart`; static-only mode: `dart run tool/check.dart --checks-only`. Source defines encoding, unchanged format (`lib/`, `test/`, `integration_test/`), analysis, unit/widget tests and one process per host-capable integration file. [CI](CI.md) uses `tool/ci.py` for selection, shards and aggregation. V1–V3 decide when to run or reuse checks.
- Prefer existing `--no-pub` check commands to avoid incidental lock changes. The encoding checker requires valid UTF-8 and rejects U+0400–U+04FF in `lib/` and `test/` Dart files, including comments/test literals; describe corruption rather than inserting literal mojibake.
- Real metadata samples: `test/data/metadata/real_samples_test.dart` needs external `ASTROPLAN_METADATA_SAMPLES` containing `expected.json`; otherwise it skips. Never commit private samples, slices or values; use synthetic `test/support/tiff_fixture.dart` fixtures.
- For authorized release builds follow [RELEASE](RELEASE.md), including `flutter build appbundle --release` and `dart run tool/check_bundle.dart`. Historical debug-to-release builds required pub resolution; do not turn an old `--no-pub` workaround into an unconditional current toolchain claim. A build is not device, signing or release acceptance.

### Schema, sessions and generation

Schema truth is `lib/data/database/app_database.dart` and `drift_schemas/`, not a copied version list. At reconciliation, `schemaVersion` is **27**; `from26To27` adds nullable `session_logs.plan_overrides`, preserving inherited global assumptions for existing rows. The supported migration floor is `kMinSupportedSchemaVersion` (currently 8).

- After a table change, update its snapshot, versioned step shapes, verification generation and schema-equality/data-preservation tests. Existing commands: `dart run drift_dev schema dump lib/data/database/app_database.dart drift_schemas/`; `dart run drift_dev schema generate drift_schemas/ lib/data/database/generated_migrations/ --no-data-classes --no-companions`; `dart run drift_dev schema steps drift_schemas/ lib/data/database/schema_versions.dart`. Check `build.yaml` and the installed generator before altering this workflow.
- Migration steps use their own `schema.<table>` shapes, never live tables. FK-action/drop-column changes use the existing table-rebuild migration pattern; explicitly map new columns so the copy never selects a nonexistent old column. Preserve transactional upgrades, data and foreign-key checks (trap 1).
- Refuse below-floor and future schemas before statements run. Startup probes the file and presents `UnsupportedDatabaseApp`; a confirmed below-floor reset preserves `.v<N>.bak`. Never reset a future schema to make it open (ADR-008 §2).
- Capture fields added by ADR-021 are nullable/unrecorded, never invented defaults. Read through `WhiteBalance.fromStored`, `FocusMode.tryParse`, `FieldOrigins.decode`, `FileEvidence.decode` and `CaptureFormat.tryParse`; unknown stored values remain unrecorded. File descriptors/labels are basenames only. Site elevation is nullable, never unknown-as-zero.
- `session_logs` is the Session root: preserve UTC-ms dates, night keys, SET NULL references and JSON snapshots via `JsonMapConverter`. Use partial `write(companion)`, never full-row `replace` that resets other columns. Pre-v16 rows remain read-only legacy records.
- Session mutations go through `SessionRepository`, one transaction per write, with pure `SessionSnapshotBuilder` snapshots. A plan name is a label via `SessionRepository.rename`, outside snapshots/copies. Result writes use `recordResult`; Saved · changed settlement uses `settleSavedPlan`.
- F19/AM-01 early reporting is implemented: `SavedNightEnd.hasStarted` permits explicitly finishing a started saved night, never a future one. `SavedNightEnd.hasEnded` still governs rollover. Preserve snapshot-owned night/time semantics and the early-result Save/Discard choice.
- Replacing a plan (New, Copy, Open, Tonight action) first calls `askBeforeLeavingPlan`: Save · Discard · Cancel. Only never-saved drafts may be deleted. Discard of Saved · changed restores its snapshot, or refuses with `SavedPlanUnavailable`. Copies are unsaved; site autosave is an edit only on a saved plan. Keep serialized autosave; do not store plan/selected target/rig in preferences when session persistence owns them. Drift edits/Save in widget tests need the real async loop.
- Equipment edits use `EquipmentProfile.withEditProvenance(original)` to preserve untouched verified fields. A field's provenance overrides its group's fallback. `showEquipmentEditor` uses pure `EquipmentDraft`; do not construct profiles in widgets or add seed specs without primary-source evidence.
- Parse user coordinates through `AstroMath.parseRightAscension`/`parseDeclination`: bare RA is hours. Edits must preserve `catalogId`.
- Weather enters through `WeatherRepository.fetchSnapshot`: UTC hours, nullable measurements. `NightWeatherSummarizer`/`NightWeatherService` own summaries and typed cache/fetch states; `WeatherFreshness` owns aging, driven by `NightClock` and resume. No widget weather arithmetic, thresholds, score or second aging path. Tests use in-memory weather stores/`NoSnapshotWeather`; served hours align to whole UTC hours.
- Catalog source is `tool/build_catalog.dart`, pinned OpenNGC input and generated `assets/catalog/catalog_v2.json`. Bump catalog version appropriately and preserve each selection's `since` (`selectionSince` is currently 2), so deleted objects do not reappear. Aliases apply only to existing catalog rows; `CatalogSeeder` rebuilds them on catalog-version changes. Keep seed writes in `TargetRepository.inOneTransaction`; widget seeding requires `tester.runAsync`. Preserve CC BY-SA notice/About attribution.

## Numbered compatibility guardrails

1. **Rig identity and migration integrity (ADR-008/011).** `EquipmentProfile.id` is an optical-rig id. Storage is Device → CameraModule → OpticalRig; domain/UI remains flat. Foreign keys are enabled on connection; device/module references use RESTRICT and capture-block/session references CASCADE. `DriftEquipmentRepository.deleteEquipment` checks shared references before deleting modules/devices. Preserve the staged transactional v8→v9→v10 migration, one-time logged orphan cleanup and removal of `equipment_profiles`; do not restore retired columns/tables from historical examples. Read the actual current schema above.

2. **Night, coordinates and opportunities (ADR-007/013).** `SessionNightResolver.resolveDefault` / `forEveningDate(CalendarDate)` own night resolution; without a site night/eveningDate are null. Use injected `Clock`, never `DateTime.now()` in domain or a DateTime's Y/M/D as a night. IANA site zones drive display through `NightTimeFormatter`; missing zones are explicitly device-zone times, not silent London. Map/GPS positions are transient until explicit site edits. Target altitudes use `VisibilityCalculator.calculateTargetAltitude` (J2000 precession, airless). `ImagingOpportunityCalculator` owns gates/reasons/windows; unknown inputs never exclude time. The shared chart/list/text and `CandidateEvaluator` must agree with the single-target calculation. Isolate work receives plain inputs, never `this`; widget tests await real async completion.

3. **Equipment units (ADR-011).** Preserve `focalLengthMm`, `focalRatio`, `pixelPitchUm` and explicit units. Stored `optical_rigs.aperture` is focal ratio N; never reinterpret it. `resolveAperture` handles N = f / D; `EquipmentLimits` owns bounds and `needsApertureReview` flags N > 32.

4. **Budget and scientific wording (ADR-009).** `CaptureBudgetCalculator` owns arithmetic; `FitAnalyzer` uses atomic placement, never sums of disjoint windows. `estimatedRequiredTime` is lights plus in-window calibration, not total-session duration. Relative stacking gain is √N of lights only, labelled through `AppWords`, never absolute/“Relative SNR.” `CapabilityCalculator` owns NPF guidance (Michaud model, explicit k from `PlanningPreferences.npfK`, field-minimum |δ|, untracked/“if untracked”); guidance never blocks a plan. Camera class is user-chosen, Unknown by default; never infer it from import. In-camera noise reduction defaults off and applies only to DSLR/mirrorless or Unknown, as one same-exposure dark within each atomic light event via `CaptureOverheads`. Tracking uses `EffectiveTracking.of(override, rig default)`.

5. **Preferences, startup and platform boundaries.** Use domain repository interfaces, not SharedPreferences in ViewModels. New planning/display keys join their repositories' `keys`; backup string values use its `string` group. New stored DB ids join `SharedPrefsPlannerStateRepository.planIdKeys` so restore/reset clears them. `StartupViewModel` owns readiness; `PlannerHarness.ready` awaits the real graph. Seeders complete before `runApp`; bootstrap failure is recoverable, weather loads after first frame and does not block readiness. Inject `LocationService`, `ReverseGeocoder`, device-zone interfaces and corresponding fakes; no HTTP/Geolocator imports in presentation/domain. Startup never requests GPS. Site changes go through SiteViewModel, not screen repository calls. Keep `timezone/data/latest_all` for IANA link-zone coverage.

6. **Sky darkness (PD-05).** Manual Bortle/SQM carries source/date or remains unknown; never scrape, default or convert Bortle↔SQM. External map coordinates come from `LightPollutionMapLink.at(lat, lon)`.

7. **Feature gates.** `lib/core/config/feature_scope.dart` owns entry-point visibility: field mode, metadata import, light-pollution context and Logbook are enabled. Text sharing remains visible. Do not recreate historical false gates, duplicate gating or hard-coded map coordinates. Metadata import uses the central route (`AppRouter.metadata`).

8. **Unknowns (SI-008).** Never display unknown data as zero or an assumed default.

9. **Row/model names.** Drift row names overlap domain names; repositories import domain models `as domain`.

10. **Navigation (ADR-015).** Use `AppRouter` constants and its static router/StatefulShellRoute. Planner/editor/picker pages that cover tabs use the root navigator. A pushed page need not change `routerDelegate.currentConfiguration.uri`; test visible navigation outcomes instead of assuming it does. Preserve current route/caller contracts when updating labels or paths.

11. **Screen-scoped ViewModels.** No monolithic `PlannerViewModel`. Existing owners include Site, Settings, SessionPlan, PlanLifecycle, NightConditions, Candidates, CaptureAnalysis, Startup, Gear, Targets and Sessions. `main.dart`/`AppViewModels` composes implementations; ViewModels consume domain interfaces and widgets watch only relevant owners. Screens do not call repositories. `viewmodel_rules_test.dart` rejects I/O/data imports and excessive ViewModel size (250 code/300 physical lines). `PlannerHarness` builds the real provider graph. An untouched plan has no target, rig or blocks; tests needing a sample use `choosePlan()` after readiness, as user edits.

12. **Theme tokens.** In presentation, no `Colors.*`, `Color(0x…)`, font sizes below 12 or shrink-wrapped tap targets (`presentation_style_rules_test.dart`). Use ColorScheme/AppPalette; add roles consistently to light/dark/field palettes. Field tokens remain red/black and the app filter does not excuse an invalid token. Theme state persists through `DisplayPreferencesRepository`. Current font authority is [design/BASELINE](design/BASELINE.md), not historical font recipes.

13. **Tonight and first run.** Tonight is a summary; calculations remain in domain/ViewModels. Reuse `WeatherText`, `MoonText`, `FitText` and `QuantityText` for shared words, durations, exposures, signed degrees and percentages. Preserve first-run loading and once-only no-site Welcome eligibility through `TonightViewModel.load`; tests must explicitly exercise first-run state rather than assuming harness construction loads it.

14. **Historical runs and current results (ADR-016 §13).** The live tracker is retired: do not restore Start/Track live routes, resume prompts or keep-screen-on. New results use `SessionRepository.recordResult`. Preserve legacy events, `ExecutionMachine.fold`, `seq` ordering, transactional counters, saved snapshots and reconciliation. Historical-run tests use `test/support/legacy_run.dart`; legacy APIs do not authorize exposing live tracking.

15. **Errors.** Handle, log through `AppLog`, or rethrow catches; never swallow them or replace structured logging with print/debugPrint. `no_empty_catch_test.dart` also rejects comment-only catches and empty `catch (_) {}` bodies. Storage failures surface as `StorageFailure` through Drift's `StorageFailureInterceptor` or preferences' `guardStorage`; domain refusals retain typed errors. UI actions use `runWithFeedback`, loads `LoadFailureView`, without raw exception strings. `CurrentSession.write` exposes `writeFailure` instead of throwing; preserve the planner banner. Tests simulate DB faults with `QueryInterceptor`.

16. **Memoization.** `NightConditionsViewModel` keys on night/target/preferences/forecast; `CaptureAnalysisViewModel` invalidates budget/fit/fill values by input generation and night. New inputs must notify or join keys. Do not cache in widgets; preserve `planner_memoization_test.dart` invalidation cases. Read MediaQuery by aspect (`sizeOf`, `paddingOf`, `viewInsetsOf`) rather than whole-query subscriptions that rebuild during keyboard animation. Performance scenarios are in `integration_test/perf_scenarios_test.dart`.

17. **Accessibility.** Keep `test/presentation/accessibility_test.dart` routes, populated data and opened PlannerSections coverage aligned with changed screens. Its sampled host scales/themes are not physical TalkBack or owner acceptance. Overflow exceptions cannot detect every clipped TextField: `test/presentation/screens/equipment/equipment_editor_fit_test.dart` measures actual text using bundled Geist. Give icon-only actions tooltips; relabelled excluded semantics need `onTap` and `enabled`. Let row text wrap; avoid fixed-height text; charts need text alternatives. Field-mode secondary-red contrast is an explicit recorded design exception (ARCHITECTURE B16), not permission for unrelated contrast regressions or an inferred owner decision to change it.

18. **Lifecycle.** Preserve file-close/reopen process-death tests and SQLITE_FULL fault injection in `test/lifecycle/lifecycle_matrix_test.dart`. Writes need feedback or handled StorageFailure. Read [TEST_PLAN](TEST_PLAN.md), [PROGRESS](refinement/PROGRESS.md) and named evidence for current device/beta criteria; old emulator availability/passes never imply physical-device completion.

19. **End-to-end.** `integration_test/core_loop_test.dart` covers the real SQLite/UI save/restart/result/Logbook/export loop and time/DST cases. Update affected keys/labels with callers; do not restore retired tracker selectors. Host-capable files run separately; Android-only captures retain separate acceptance. Read current driver/test sources for device invocation rather than replaying a historical emulator command as fresh evidence. Wait for covering snackbars before tapping bottom actions.

20. **Identity and launch.** Use `AppIdentity.appName` (“Culmina”), canonical `io.github.buffur.culmina` and matching metadata channel. Internal package `astroplan`, `.astroplan` format and manifest `app: AstroPlan` remain compatible internals. `tool/culmina_mark.py` owns generated icon/splash/launch geometry and colours; change the generator, regenerate intended outputs and format generated Dart. Never hand-edit native layers/PNGs or generated geometry. Android supplies the still mark/`splashGone`; Flutter `LaunchGate` alone plays the full approved gesture, revealing once after gesture AND readiness. Preserve reduced-motion, error and background-pause behavior covered by identity/launch tests; never shorten or duplicate the gesture.

21. **Signing.** Owner keys, `.jks` and `android/key.properties` must never be created, read, printed, requested or committed by an agent. Current release configuration falls back to debug signing only without the properties file; `tool/check_bundle.dart` rejects debug-signed bundles. Uploads require a higher pubspec build number/versionCode; `AppIdentity.version` matches the version name. Follow [RELEASE](RELEASE.md), never historical delivery permission.

22. **Privacy and third parties.** Preserve opt-in `OptInReverseGeocoder`, off by default: no coordinates sent otherwise, no silent saved-site/default-position lookup. F23 name proposals are implemented for explicitly picked new positions, respecting manual edits, consent and stale-request ownership (`SiteViewModel.lookUpPlaceName`, site editor). Use `AppIdentity.userAgent` for third-party requests. New outbound services/data require privacy/Data Safety updates in `privacy/index.md` and [COMPLIANCE](COMPLIANCE.md). Ads/subscriptions/provider changes need the relevant owner decision and current provider-terms review; historical free-tier statements do not establish current commercial rights.
