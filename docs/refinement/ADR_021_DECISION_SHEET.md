# ADR-021 decision sheet — capture contract and v26 persistence (F03)

**Status: PROPOSED for the owner's local acceptance (F03 A1). Not an accepted ADR, not
implemented.** Prepared 2026-10-18 in the full final-plan run. The semantics D3–D5 (owner,
2026-10-18, DECISIONS E.1) and AM-04 are already accepted and are not asked again; this sheet
asks only for the exact encodings, rules and reference vectors that implement them. On acceptance
the text below is recorded as ADR-021 in `docs/DECISIONS.md` and F03's v26 migration starts.

Sources: roadmap §3 F03–F11 and §8 CP contract; FINALIZATION_REVIEW §21/§37; DECISIONS RA.D
round 2A (PD-05–PD-14, PD-21) and E.1 (D3–D5, AM-04); `RA_R2B_CAPTURE_SCIENCE.md` §3.2 (S1–S4)
and R-O2; current code (`capture_block.dart`, `camera_class.dart`, `session_snapshot_builder.dart`,
`session_manifest_codec.dart`, `capture_budget_calculator.dart`, `equipment_foundation_tables.dart`).

## Numbered choices (each with a recommendation)

| # | Choice | Recommendation (R) | Alternative considered |
| --- | --- | --- | --- |
| C1 | White balance encoding on `capture_blocks` | Nullable `wb_mode` text: `auto`, `preset`, `kelvin`, `custom`; NULL = unrecorded. `wb_preset` text for `preset` only: `daylight`, `cloudy`, `shade`, `tungsten`, `fluorescent`, `flash`. `wb_kelvin` integer for `kelvin` only, sanity bound 1,000–40,000 K (not a device range). `wb_tint` real, optional with any mode but `auto`, as the camera shows it, sanity bound −1,000…1,000, no unit claimed. An unknown stored mode/preset reads as unrecorded (future-enum rule) | One JSON column `wb` (fewer columns, but not queryable and a second encoding path) |
| C2 | WB file evidence | Not a block value: a file's EXIF WhiteBalance (Auto/Manual), LightSource code or DNG AsShotNeutral vector is kept only as the **evidence** of the `wb` origin (C4). A file proposes `auto` only from EXIF Auto; Manual/LightSource/AsShotNeutral propose nothing for `wb_mode` and are shown as evidence; never converted to Kelvin | Propose `custom` from AsShotNeutral (rejected: it would claim a setting the user did not choose) |
| C3 | Focus mode (AM-04) | Nullable `focus_mode` text: `af`, `mf`; NULL = unrecorded. Explicit entry only (no EXIF/FITS inference). Offered for Phone, DSLR/mirrorless and Unknown; kept and shown read-only if present on an astro rig's block. No calculation, timing, calibration identity or control uses it | A boolean (rejected: cannot say "unrecorded") |
| C4 | Per-field origins (D5) | Nullable `field_origins` text, JSON object `{field: origin}`. Fields: `frameType`, `filter`, `exposure`, `count`, `sensitivity`, `binning`, `wb`, `focusMode`, `fileSize`. Origin = `{"k": kind, "d": descriptor, "e": evidence?}` with kind `entered`, `copied` (from a block), `inherited` (calibration from lights), `file`, `declared`. `d` is an immutable display descriptor fixed when the value was accepted ("from the Ha block · 300 s", "IMG_0845.dng"), at most 80 characters; `e` an optional small typed map (e.g. `{"tag": "ExposureTime (33434)"}`, `{"asShotNeutral": [0.47, 1, 0.62]}`). An absent field or a NULL column = origin unrecorded, never `entered`. A user edit replaces only that field's origin with `entered`. No live link to a source block or file (no foreign key) | One table row per field (rejected: a join for every block read and an FK history problem when a source block is deleted) |
| C5 | Origin privacy | Descriptors carry a basename only (no path or URI), no raw header dump, no GPS, no capture time beyond what a block already stores | — |
| C6 | Block file evidence (D3/D5) | Nullable `file_evidence` text, JSON: `{"bytes": int>0, "format": "dng"|"jpeg"|"heic"|"fits"|"tiff"|"recognized:<ext>", "read": true|false, "width": int?, "height": int?, "bitsPerSample": int?, "compression": "none"|"lossless"|"lossy"|"unknown", "binning": int?, "label": basename}`. One file per block (the latest accepted pick). `read: false` (recognized, unread) carries no width/height/compression (D3 A) | Separate columns per item (rejected: eight columns used only by storage) |
| C7 | Rig capture format (PD-06) | `camera_modules` gains nullable `capture_format` (`dngUncompressed16`, `fits16`, `fits32float`, `compressedRaw`, `jpegHeic`, NULL = unknown), `capture_format_source` (`file:<basename>` or `declared`), and `raw_file_size_evidence` (the same JSON as C6, describing the file the existing `averageRawFileSizeMB` came from; NULL for every existing row = association unrecorded). The existing `averageRawFileSizeMB` and its provenance columns are unchanged | Add bits/compression as separate columns (round 2A's wording; folded into the enum because only these five formats have a defined theoretical rule) |
| C8 | Storage evidence order (D3/D4) | Per light or calibration block, the first that applies: (1) the block's own compatible measured file (C6); (2) the rig's compatible measured file (C7); (3) theoretical payload (C10); (4) Unknown with the action "Choose one file" or "Enter a size". Compatible = same format when both are known, same output dimensions when both are known, and the same binning when both are known; anything not known on one side is not a conflict for (1)/(2) but is shown. A changed rig format/resolution makes the rig's evidence incompatible until reconfirmed. Camera class never selects a branch | Prefer theoretical over measured when both exist (rejected: measured is evidence of the real container) |
| C9 | Measured bytes and binning (D4) | A measured file's bytes are used as they are; they are never scaled by binning, in either direction. A measured file whose binning differs from the block's is incompatible, not rescaled | Divide by bin² (rejected: the file is already the output) |
| C10 | Theoretical payload (D4) | Only for: an uncompressed DNG (Compression = 1, BitsPerSample read from that file), a supported FITS layout (NAXIS = 2, BITPIX 8/16/32/−32/−64, read from a file), or a format the user declared and confirmed (`dngUncompressed16`, `fits16`, `fits32float`). Pixel payload = W_out × H_out × bitsPerSample / 8. FITS file = payload padded to a 2,880-byte multiple + header records (the read file's count; one record when declared). DNG: pixel payload only, labelled "pixel data; the file adds a small header that depends on the camera's software" (S1's 6,700 B is one writer's, not a rule). Compressed or lossy formats: no theoretical value | Add S1's 6,700 B to every DNG (rejected: writer-specific) |
| C11 | Geometry normalization for theoretical size (D4) | W_native/H_native = the rig's resolution (full sensor). For a block at binning b: W_out = ⌊W_native / b⌋, H_out = ⌊H_native / b⌋, once. From a FITS file: when XBINNING = YBINNING = k is present, native = NAXISn × k (NAXIS is the binned output); when absent or asymmetric, the file's geometry is not normalized and supports a theoretical value only for a block at the same output size, otherwise Unknown | Treat absent XBINNING as 1 (rejected: some writers omit it for binned frames) |
| C12 | Recognized but unread file (D3 A) | One user-picked file's byte length estimates one frame of that block, labelled "mode not read; compressed sizes vary with content", `read: false`; it supplies no dimensions or compression and can never feed C10 | — (D3 A accepted) |
| C13 | Sensitivity kind from class (AM-04) | No per-block ISO/gain selector. Phone, DSLR/mirrorless → ISO; astro colour/mono → gain; Unknown → the block offers "Choose a camera class" and otherwise stores `gainKind = unknown` with no value. Existing stored kinds/values are kept and shown as recorded even if the class changed | Keep the Unknown class's either-choice (rejected by AM-04) |
| C14 | Exposure entry | Positive decimal seconds or a fraction `a/b` (integers, b ≠ 0, optional spaces, optional trailing "s"); stored as canonical seconds (double) within the existing bounds (0 < t ≤ 3,600 s). The text is not stored | Store the typed text (rejected: two representations) |
| C15 | Calibration identity (CAL-1, TD-107) | Darks: (exposure, sensitivity kind + value, binning). Flats: (normalized filter, binning). Dark flats: (the flats' exposure, sensitivity, binning). Bias: (sensitivity, binning). Filter comparison: trimmed, case-folded equality; no alias table ("H-alpha" ≠ "Ha"). An unknown sensitivity never proves coverage of a known one. WB and focus mode are never part of the identity | Fuzzy filter aliases (rejected: guessing) |
| C16 | Relative-gain groups (O2b, F11) | One group per (normalized filter, exposure, sensitivity kind + value, binning) of light blocks; a group with any unknown sensitivity or binning stays a separate "not comparable" group. Primary figure: √N against one frame of the same group; Details: √(T / T_plan) with T = N·t per group. Never summed across groups; never called SNR | Combine groups with an idealization label (rejected for the primary figure; may be offered in Details only with that label) |
| C17 | Snapshot (version 1, additive) | Each snapshot block gains `wb` (`{mode, preset, kelvinK, tint}` or null), `focusMode`, `origins` (as C4), `fileEvidence` (as C6). The rig section gains `captureFormat`, `captureFormatSource`, `rawFileSizeEvidence`. A snapshot without these keys reads them as unrecorded. `currentVersion` stays 1 | Bump to 2 (rejected: old readers would treat every new snapshot as unreadable) |
| C18 | Export manifest (version 2, additive) | Block entries gain `white_balance`, `focus_mode`, `field_origins` (kind + descriptor only, no evidence values), `file_evidence` (format, read, dimensions, bytes; label = basename). `EXPORT_MANIFEST.md` records them; readers ignore unknown keys as now | — |
| C19 | Migration v25 → v26 | One step `from25To26`: add the nullable columns of C1/C3/C4/C6 to `capture_blocks` and of C7 to `camera_modules`; no data rewritten; every existing row reads as unrecorded. New `drift_schemas` v26 snapshot and generated steps. Newer-than-app refusal unchanged | — |
| C20 | Required rig inputs (F05 A3) | Sensor width/height → field of view (CALC-13) and framing; resolution → pixel pitch check, theoretical storage (C10); pixel pitch → pixel scale (CALC-12) and NPF (CALC-17); focal length → FOV, pixel scale, NPF; focal ratio → NPF. Each is required as today (ADR-011); a photo supplies focal length, focal ratio and dimensions, the 35 mm equivalent derives sensor size where the existing import already does; nothing is defaulted | Relax required inputs (excluded by the roadmap) |
| C21 | FITS → rig/block (F10) | Rig: XPIXSZ/YPIXSZ (µm, binned convention → native = value / XBINNING; asymmetric → conflict, not proposed), native resolution (C11), FOCALLEN (mm, `softwareSetting` provenance), INSTRUME (camera name proposal), TELESCOP (identity text only). Block: EXPTIME, else EXPOSURE (both present and different → conflict shown), GAIN (gain kind), XBINNING (symmetric only), FILTER (as written, trimmed), BITPIX/NAXIS → file evidence. OFFSET, CCD-TEMP, SET-TEMP and DATE-OBS are read and shown as evidence only (no new block field) | Map CCD-TEMP to a block field (excluded: not an approved field) |

## What acceptance means

Accepting this sheet (all recommendations, or with numbered changes) lets F03 implement C19 and
the dependent tasks F04–F12 use the encodings above. It decides no new product scope: no new
provider, partial rig, hardware control, numeric focus, absolute SNR or class-derived sensor fact.
The FITS sample gate (F03 A5) is separate: see PROGRESS's attention register.
