# Independent final review: Hybrid / Geist Flutter migration

This is advisory QA only. It is read-only and confers no owner acceptance. **The completion claim is not supported by the evidence.** The domain, persistence and Undo work is sound. But visual fidelity and 200% text both fail on defects visible in the project's own Android and host captures, and the matrices mark rows VERIFIED with evidence that does not cover them.

## Findings, ordered by impact

### F1 · Confirmed defect: the "Weather" tab is clipped at 200%
- **Where:** `lib/presentation/screens/details/night_moon_screen.dart:101-121`. The `TabBar` has fixed, non-scrollable tabs (`Tab(text: 'Weather')`).
- **Evidence:** the label is cut off ("Weathe…") in:
  - Android: `native/run-2026-10-21/moon-dark_200.png` and `weather-field_200.png`
  - Host: `matched/flutter/moon_dark_200.png`
  - The browser reference `browser-moon-dark200.png` shows "Weather" in full.
- **Why it matters:** this contradicts A-SHELL-04 / large-text "without capped text", A-NIGHT-01, A-MOON-04 and B24. The V1 audit says it reviewed "Moon … light 200 %" and recorded no defect.
- **Correction:** let the tab labels wrap to two lines or make the tab bar scrollable at large scale, size the bar for the text scale, and add a 200% host test that checks for clipping.

### F2 · Confirmed defect: Plan assumptions labels lose their units at 200%
- **Where:** `plan_overrides_editor.dart:190-195`. The single-line `labelText` ellipsizes.
- **Evidence:** `native/.../plan-overrides-reopened-light_200.png` shows "Setup outside the window (mi…" and "Theoretical file size per frame …". The minutes and MB units disappear.
- **Why it matters:** this breaks the explicit-units invariant (CLAUDE.md). Affects A-PLAN-10 and B23.
- **Correction:** move the unit into `suffixText` or a multi-line `label`, or use the web's label-above-field layout. Add a 200% assertion.

### F3 · Confirmed defect plus an unmigrated composition: the full-page block editor
- **Spacing:** `capture_block_dialog.dart:797-1096` puts no space between fields. On Android (`block-editor-keyboard-light_100.png`) each floating label sits on the border of the field above. The web spec is a one-column gap of 20.
- **Composition:** compared with `browser-plan_editor-light100.png`, the native editor does not adopt:
  - the segmented frame-type control and label-above fields
  - the exposure examples hint
  - the live "= 1 h 40 min of integration" line
  - the "From a photo" disclosure and the rig context line
  - the full-width Apply action
- **Status conflict:** the audit itself says editor references are "unmatched" (`VISUAL_COMPARISON_AUDIT.md:94-98`), yet A-PLAN-06, -07 and -08 are marked VERIFIED.
- **Correction:** add the field gaps, capture a matched host state of the editor, and then either adopt each element or record it as a deviation.

### F4 · Evidence quality: boilerplate "VERIFIED" citations in Matrix A
- About 60 rows in `WEB_DESIGN_INVENTORY.md:80-164` cite "G2 host · V1 matched visual · N1 native roots (3 themes × 100/200 %)". They do this for behaviours that N1 and V1 never exercised:
  - target search, calibration proposals, WB/Kelvin, Logbook filters/search, exports
  - Library editors and dirty-edit handling
  - rig and target Undo
- **What N1 actually covers:** the eight routes are captured only at the top of each page. Rig/target/site/Logbook flows are exercised only for Save/reopen, partial result, Logbook entry Undo, active-site Undo and the rig editor at 200%.
- **What V1 actually covers:** an eye review of light 100% for every root plus a few samples. All 72 records in `matched/gallery/manifest.json` are still `"awaiting visual inspection"`.
- **Contradictions:** rows still carry text such as "matched all-root rerender pending", "final preservation run pending" and "work in progress; targeted failure/restore tests pending" alongside VERIFIED. `WEB_TO_FLUTTER_MIGRATION.md:113,145,167-178,204` likewise still says "pending / a new run is required".
- **Correction:** cite real evidence per row, mark "native not exercised" where true, and update the gallery review statuses.

### F5 · Evidence labels overstate what the Android run did
- **Text scale and theme are simulated in-process.** `hybrid_migration_smoke_test.dart:366-371` sets `textScaleFactorTestValue` and `platformBrightnessTestValue`. The Android system font setting (including nonlinear scaling) and the system dark setting were never used. A-SET-08 still claims "N1 system text scaling at 200 %".
- **Android system Back was not used.** Back is `tester.pageBack()`, which taps the app-bar button.
- **The dirty-editor guard was not exercised on Android.** In the block editor the test taps the explicit Cancel button (`:261`), so the dirty Close/Back confirmation path was never run on the emulator.
- **Correction:** relabel these as simulated, and add `binding.handlePopRoute()` or an adb back-key check on a dirty editor.

### F6 · Evidence quality: a skipped suite reported as PASS
The full gate summary lists "PASS E2E (host): hybrid_migration_smoke_test.dart", but the log (`full-gate-2026-10-21-final.log:7456`) says "All tests skipped". This is by design (`skip: !Platform.isAndroid`), but the summary should say SKIPPED.

### F7 · Composition deviation not recorded: Settings sections keep the root navigation
- Settings → Planning (and the other sections) keep the bottom navigation. The web hides it on detail screens, as A-SHELL-01 requires.
- At 200% the 2×2 navigation plus the Save/Cancel footer take about 30% of the height: compare `matched/flutter/settings_planning_light_200.png` with the browser capture.
- Native sliders are also inset from their range labels and show division ticks.
- **Correction:** push the sections above the shell, or record this as a deviation (D-05) for the owner.

### F8 · Contrast risk needing an owner decision: field-mode primary action
- The field action is black on #AA0000, about 2.7:1 (`hybrid_tokens.dart:77-79`). It is visible as "Save plan" in `plan-field_200.png`.
- The documented exception (`ARCHITECTURE.md:776-779`) covers **secondary text only**. Tertiary #880000 is about 2.1:1.
- `accessibility_test.dart:341ff` turns contrast checking off entirely in field mode. In practice that is the general waiver the brief rules out.
- The pairing comes from the JSON, so this is an owner decision rather than a defect: either widen the documented exception explicitly or change the action colour.

### F9 · Source-grounded risk: Geist weights
- Geist is bundled as one variable TTF (wght 100–900; `assets/fonts/Geist.source.json`, `pubspec.yaml:85-87`).
- There is no `FontVariation` anywhere in `lib/`, and no test shows that `FontWeight` 500/600 actually selects real instances on Impeller/Android.
- If it does not, 500 renders as 400 and 600 or above as synthetic bold. That would undercut the weight and line-height fidelity the brief asks for.
- **Correction:** add a real-font test comparing glyph widths at w400 and w500, or set `fontVariations` in the theme.

### F10 · Provenance wording: the bytes-per-frame override
- **Label and hint:** the field label is "Theoretical file size per frame (MB)" and its hint is "Use file / rig evidence". The web's hint, "A planning figure, not measured from your files", was dropped. In this app "theoretical" means computed payload, while the stored basis is `planEstimate` ("user entered"; `storage_text.dart:17`).
- **No reclassification:** the value is never treated as measured evidence, so the core rule holds.
- **Silent replacement:** the override replaces every block's measured file evidence (`capture_analysis_viewmodel.dart:95-104`), but nothing on screen says which evidence was set aside.

### F11 · Documentation governance
- `docs/DATA_MODEL.md:3` still says "Current schema: v25".
- Schema v27 `session_logs.plan_overrides`, the fixed-margin classification rule, the new storage basis and stored Undo are not recorded in DATA_MODEL, DECISIONS, SCIENTIFIC_INTEGRITY or FEATURE_STATUS. Only EXPORT_MANIFEST was updated. CLAUDE.md requires actual-state updates in the same change as a schema change.

### F12 · Minor visual gaps not recorded as deviations
- Weather drops the web's "Clearest around … / cloudiest around …" line. Its coverage line appears only when coverage is incomplete (`night_text.dart:112-124`), whereas the web always shows "Coverage 11/11".
- Tonight's Night row drops the "10 h 55 min dark" figure, and the plan summary drops "M42".
- The rig editor is still a Material `AlertDialog` that mixes label-above and floating-label fields (`rig-resolution-light_200.png`).

### Checked and found sound (source plus tests)
- **Plan overrides end to end:**
  - Null inherits the global setting and explicit zero is kept.
  - Interframe seconds feed the budget, the fit and Fill-window.
  - Setup stays outside the window.
  - The fixed margin changes only the Fits/Tight classification (`fit_analyzer.dart:222-230`).
  - New plan clears the overrides; copy, settle, open and discard carry them (`plan_lifecycle_viewmodel.dart:179-279`, `drift_session_repository.dart:475-546`).
  - Snapshots record both the explicit and the effective values; old snapshots and manifests read as "no overrides".
  - The v26→v27 migration is additive.
  - The native run confirmed globals unchanged, Save/reopen and the backup round trip.
- **Stored Undo:**
  - `drift_deletion.dart` deletes and restores the exact rows in one transaction, in dependency order, using plain INSERT, so a conflict rolls everything back.
  - A shared camera or device is restored only if this deletion actually removed it.
  - A restored reference is relinked only if the row is otherwise unchanged.
  - IDs are AUTOINCREMENT, so a deleted ID is never reused.
  - Host tests cover conflict/retry, same-timestamp edits and a physical SQLite reopen. On Android only the Logbook entry and the active site were exercised; rig and target Undo are host-only.
- **Scoped Night/Moon/Weather:** the listener-leak fix (`night_conditions_viewmodel.dart:47-49`) is correct, and browsing a night did not change the plan (N1).
- **Block editor guards:** the dirty-state guard, typed values per camera class, unknown-kind handling, async photo-read safety (the messenger is captured) and the keyboard-lifted footer are all correct in source.
