## Original findings

**1. Result form discards input on Back: resolved in code.**
- **Snapshot:** `_initialInput` is taken right after the form fills (`results_screen.dart:143`). "Changed" means the current input differs from it, compared field by field (`:67`), and the per-block counts are included.
- **Back, system Back, Cancel and Escape** all go through `_leave` (`:69-89`). It asks first only when something changed.
- **Unchanged exit** closes the screen directly (`:83-88`). No test covers this path.
- **Save:** a successful save goes to the Logbook (`:218`). A stale save reloads the entry, refills the form and takes a new snapshot (`:214`, the view model at `results_viewmodel.dart:213-215`). Any other failure keeps the typed input.
- **Spacing and footer:** fields are 20 dp apart (`:240`). The footer holds Cancel and Save and is padded by the keyboard height (`:258-291`).
- One layout note: Cancel sits alone on its own right-aligned row above a full-width Save.

**2. Detail screens keep the bottom nav: resolved.**
- The shell's builder shows the nav only on the four root paths (`app_router.dart:112-120`). I checked go_router 18.0.1's own code: the shell uses the location of the page pushed inside it (`match.dart:384-389`). A screen opened over the tabs doesn't change it.
- The tab navigators stay in the same place in the widget tree, so each tab keeps its stack. The test at `app_shell_navigation_test.dart:315-329` checks this.

**3. Field-mode button missing on secondary screens: resolved.**

- The added button is counted when measuring the title's height (`:57`).
- Duplicate detection only checks top-level actions. Every current caller passes the button at top level, so this is fine today.

## New problems found

1. **Site editor: Escape asks about unsaved changes even when nothing changed.** Escape calls `_onBack` directly (`site_editor_screen.dart:471`), and `_onBack` always shows the "has changes that are not saved" dialog (`:394-398`). Back only reaches it when `canPop` is false, but Escape skips that check.
   - **To reproduce:** open a site, click into a field without typing, press Esc. The dialog appears.
   - The other three editors check for changes inside their own exit function, so they don't have this problem.

2. **Escape does nothing until something inside the editor has focus.** `CallbackShortcuts` only receives keys when focus is inside it. A newly opened screen focuses its own route, which sits above the shortcut handler, and none of the four editors autofocuses anything.
   - **To reproduce (Windows or hardware keyboard):** open the block editor, results, site or overrides editor and press Esc without clicking a field. Nothing happens.
   - The only Escape test types into a field first (`block_editor_hybrid_test.dart:71-75`). Results, site and overrides have no Escape test.

3. **The new keyboard tests can't fail.** `results_screen_test.dart:179-183` and `sites_screen_test.dart:172-176` set `physicalSize` to 412×915 without setting `devicePixelRatio`. Assuming the usual test default of 3.0, the logical screen is about 137×305. Then Save's bottom edge is always ≤ 615, even with no keyboard padding.
   - These are host tests with a simulated keyboard inset. Even once fixed, they are not evidence of real Android keyboard behaviour.

4. **Result form: back-swipe gestures are always blocked (low).** `canPop: _leaving` (`results_screen.dart:244`) is false even for an untouched form. That disables the iOS back swipe and Android's predictive-back preview. The site editor uses `canPop: _leaving || !_builtChanged`, which only blocks after a change.

5. **Tonight type sizes only partly follow the original blend.** The wordmark, welcome line, subtitle, rig line (14/1.55) and the measure figures (12 px labels, 15/500 tabular values, 20 px gap, matching `styles.css` `.plan-measures`) match. Two roles don't:
   - The plan reason is 12 px / 1.6 (`status_block.dart:104-109`). Blend sets `.plan-reason` to 14 px / 1.55 (`hybrid-refinement.css:12`).
   - The condition-row value is 15 px (`tonight_home_screen.dart:683-685`). Blend sets `.condition-value` (used at `app.js:89`) to 16 px (`hybrid-refinement.css:13`).
   - I read the CSS cascade from source and didn't compute it in a browser.
