## New findings

### N1 · Confirmed defect: the tint check is skipped when Details is closed

This is a regression from OPEN-01.

- **Where:** `capture_block_dialog.dart:1081-1147`.
  - The tint field (with its `_validateTint` check) now lives inside the Details disclosure.
  - `BlockDisclosure` builds its children only when open (`block_editor_parts.dart:317`). A closed disclosure therefore removes the field from the `Form`.
  - `_submit` (`:658-663`) checks only the fields still mounted, then builds the block via `_build` (line 488), which calls `_whiteBalance()` (`:500`).
- **Trigger:** on a DSLR or phone rig, a light block with white balance set to Preset, Kelvin or Custom:
  1. open Details;
  2. type tint `2000` (or `abc`);
  3. close Details;
  4. tap Add block or Apply changes.
- **Expected:** the error shows next to the tint field and the editor stays open, as `:365-373` intends.
- **Actual:**
  - For `2000`, `WhiteBalance.preset/kelvin/custom(tint: 2000)` throws an `ArgumentError` (`capture_evidence.dart:65-66`). The error is not caught in `_submit`, so the tap does nothing and no message appears.
  - For `abc`, `double.tryParse` returns null and the typed tint is **silently dropped** from the saved block.
- **Test gap:** the test named "an out-of-range Kelvin **or tint** fails by its field" (`block_settings_test.dart:383-394`) only covers Kelvin. No test enters an invalid tint.
- **Brief impact:** this contradicts brief §8 "нові регресії усунені" (new regressions removed). It also undercuts A-PLAN-07's "Kelvin/tint bounds" citation.
- **Fix (bounded):** either keep the disclosure's children mounted while closed (for example `Offstage`/`Visibility(maintainState: true)`, so the `FormField` stays registered), or run `_validateTint` in `_submit` and open Details when it fails. Add a test for an invalid tint with Details closed.

### N2 · Evidence quality: the final code has no clean full gate, and the matrix definitions are stale

This is not a code defect.

- **Final-code gate:** `full-gate-2026-10-21-r4.log:7772-7806` ends "Quality gate FAILED" with `exit=1`: `secondary_consistency_test` failed, 2425 passed.
  - The re-check (`:7807-7810`) records format, analyze and "+53: All tests passed", but **no command**, so it cannot be confirmed that it included `secondary_consistency_test`.
  - `full-gate-2026-10-21-open01.log` likewise failed (`exit=1`) and was followed by an 11-test re-check.
- **Stale definitions:** Matrix A's G2 definition (`WEB_DESIGN_INVENTORY.md:18`) still calls `after-review.log` the "final code", and N1 still cites r2. A-PLAN-06 cites "N1 r3", and nothing cites r4.
- **Native timing:** the r4 native run predates the final 2 px slider change (the ledger says so).
- Under AM-05, targeted re-checks can close a Task, so this is not a blocker. But "full quality gate on the final tree" is not literally supported.
- **Fix:** record the re-check commands and update the G2/N1 definitions to `r4`. Leave the consolidated full gate for G1/F26.

### Risks (unconfirmed)

- **Screen-reader labels:** `BlockField` and the overrides editor put the label on a non-container `Semantics` wrapped around a `TextFormField`, and hide the visible label from screen readers. No test asserts that the label lands on the text-field node itself (`isTextField` + label), so TalkBack's reading is NOT VERIFIED (L-6).
- **Tonight fit-line icon:** a fixed 17 px icon (`status_block.dart:142-151`) does not scale and looks undersized at 200 % (`r4/tonight-light_200.png`). Cosmetic.
- **Darkness length computed in the UI:** Tonight's "dark" length is calculated in the presentation layer (`tonight_home_screen.dart:503`), falling back to the window edges when dusk or dawn is missing. It is consistent with Moon and Weather in the fixture. Minor layering concern.
- **Hidden tint:** an existing block's tint is hidden while Details is closed, and the Details summary lists only binning and timing.
