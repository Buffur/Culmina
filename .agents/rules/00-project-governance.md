# Project Governance Rules

Updated 2026-10-17; canonical scope and verification rules are in CLAUDE.md.

- Use the current owner-approved Task, refinement PROGRESS and the approved FINAL_COMPLETION_ROADMAP (2026-10-18; POST_ROADMAP_PLAN for the registers and S-ID aliases); historical roadmap phases are not the active queue.
- An explicitly supplied implementation Task authorizes its full cycle, including multi-file, architectural or database work already within its scope. Do not request duplicate approval.
- New unresolved decisions or material scope expansion require the relevant owner decision before that implementation; continue independent authorized work where possible.
- Research, reassessment, planning and validation never silently become application implementation.
- Do not automatically begin another Task or Stage unless the owner explicitly approved the bounded group and stop conditions.
- Distinguish verified facts, assumptions, recommendations and unresolved risks. Use CLAUDE.md's Verification Policy without restating it here.
