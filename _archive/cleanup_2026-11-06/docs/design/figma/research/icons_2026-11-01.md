# Culmina After-Dark 1.2 icon research

Date: 2026-11-01. Research only. The owner requested an independent review of possible icon additions and replacements while the timeline comparison study is developed. No icon changes, plugin installations, Flutter edits or live Figma inspection were performed by this researcher.

## Evidence and scope

The current [After contract](../TARGET_DESIGN_SYSTEM.md), [navigation catalog](../components/navigation.md), [forms catalog](../components/forms.md) and [workflow/timeline research](workflow_and_timeline_2026-11-01.md) establish the intended design scope. The owner-approved compact rows, labeled navigation, Capture overflow and separate Tracking block remain the baseline. This report proposes candidates; it does not adopt a new icon system or override those decisions.

Read-only source inspection confirmed:

- [Hybrid icon geometry and renderer](../../../lib/presentation/shared/hybrid_icon.dart) combine custom Hybrid geometry with a Lucide Weather subset. The base viewBox is 24 units, with round caps/joins; the renderer defaults to 20 logical pixels and a 1.7-unit stroke.
- [Root navigation](../../../lib/presentation/navigation/app_shell.dart) maps Tonight, Logbook, Library and Settings to the existing moon, book, library and settings icons. These are current source facts, not proof that every live Figma instance has the same geometry.
- [Context controls](../../../lib/presentation/shared/context_line.dart) use homePin and planner identities. The current After navigation contract separately specifies 16px Geo/Date glyphs inside at least 48px targets; that After treatment should not be confused with production renderer values.
- The icon dictionary contains multiple moon, pin, cloud, chevron and overflow geometries. This is a consistency opportunity, not evidence that every variant is defective or interchangeable.
- [Bundled license notices](../../../assets/fonts/LICENSE-Lucide.txt) preserve Lucide ISC and applicable Feather MIT notices. The [license registry](../../../lib/core/theme/font_licenses.dart) registers that asset.

The recommendations below draw on these sources and the supplied design context. No fresh live-Figma icon-by-icon audit, legibility test, accessibility test or usability experiment was performed.

## Recommended approach

Retain Culmina's accepted outline family and use Lucide to fill genuine gaps. First normalize duplicate role geometry; do not replace the entire navigation simply to introduce a new library. Geist remains unchanged. A useful isolated trial would compare the current and proposed overflow, warning and duplicate-role glyphs at their actual rendered size.

| Role | Candidate or action | Reason and boundary |
| --- | --- | --- |
| Geo / Date | Retain the current identities; [map-pin](https://lucide.dev/icons/map-pin) and [calendar-days](https://lucide.dev/icons/calendar-days) are consistent replacement candidates | Recognizable at compact sizes. Keep separate site/date actions, labels and hit regions. |
| Capture overflow | Standardize one [ellipsis-vertical](https://lucide.dev/icons/ellipsis-vertical) treatment | Keep the existing single menu affordance. Do not turn it into a drag handle or add a second reorder symbol. |
| Overflow menu items | Pencil, Copy and Trash beside actual Edit, Duplicate and Remove actions | Add no unimplemented actions. Removal keeps an explicit destructive word. Do not restore the owner-excluded Move up/down items. |
| Add block | Optional Plus beside the label | Familiar action identity. Add only if the one-line label and current button arrangement still fit. |
| Fill the window | Keep the label and proposal summary without another icon | Expand/maximize arrows suggest resizing; sparkle suggests an unexplained automatic or AI action. Neither clearly describes applying a frame-count proposal. |
| Build calibration frames | Keep text-only | Layers can be confused with stacking; Camera suggests taking exposures. The existing action label is more precise. |
| Tracking | [Triangle-alert](https://lucide.dev/icons/triangle-alert) only when there is an actual warning | Retain explicit warning text. A permanent decorative icon would add density without clarifying the setting. |
| Site / Night / Target / Rig rows | Keep the compact rows text-led | Four added leading icons would consume the space the owner deliberately removed. Chooser screens can retain their existing identity icons. |
| Rig identity | Use class-specific Camera or Phone when a chooser requires an icon | Do not use a universal [Telescope](https://lucide.dev/icons/telescope): the current example is DSLR/135mm, and other rigs can be phones or cameras. |
| Estimate metrics | Add no new icons | Labels and subdued metric blocks already separate the facts. Relative gain is not a trend, a quality score or absolute SNR. |
| Timeline lanes | Optional Sun / Moon / Camera beside written lane labels | Never replace event names or exact times with glyphs. Preserve timezone, next-day markers and Unknown states. A crescent used as a category symbol must not imply the actual phase. |
| Root navigation | Retain the accepted moon / book / library / sliders identities | A library-wide replacement has no demonstrated benefit. Do not reintroduce an extra selected-tab check. |

These are semantic design judgments rather than claims that Lucide prescribes particular application meanings. In particular, visually similar Target and Locate icons must remain distinguishable if they occur together.

## Geometry and interaction guidance

Use one documented 24-unit outline grid with round caps and joins. [Lucide's design language](https://lucide.dev/contribute/icons/design-principles) uses a 24px canvas and 2px stroke. Culmina's existing 1.7-unit treatment is a local choice, not a Lucide requirement. Retain it when matching existing geometry; compare a native 2-unit alternative separately instead of mixing arbitrary weights.

Use the current 16px Geo/Date treatment and 20px row/action candidate size; preserve the accepted root-navigation dimensions. These are local proposed/application values, not universal accessibility minima. Inspect actual 16px specimens at 100% because a nominal glyph box does not guarantee that small internal details remain clear. In this renderer stroke units scale with the icon's viewBox, so a 1.7-unit stroke is not necessarily a 1.7px visible line at every output size.

Keep semantic neutral ink and existing state colors. Avoid a separate accent for every category. Meaningful component/state graphics should meet the 3:1 adjacent-color benchmark in [WCAG non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html); text has its own contrast requirement. Decorative redundant imagery is a different case from an icon required to recognize an action.

Keep at least 48-by-48dp Android touch areas even when glyphs are smaller, following [Android accessibility guidance](https://developer.android.com/guide/topics/ui/accessibility/apps). Name icon-only controls by their action; redundant decorative icons should not cause duplicate screen-reader announcements. See [Lucide accessibility guidance](https://lucide.dev/how-to/accessibility). A Figma specimen alone does not verify native semantics, focus or gesture accessibility.

## Licensing and delivery boundary

[Lucide's official license](https://lucide.dev/license) permits use, modification and distribution with retained notices. When copying SVGs into Figma or exported assets, retain provenance and the applicable ISC/MIT notices in the deliverable; do not remove the existing bundled notices. The owner's permission to copy reference patterns is not a separate grant to redistribute arbitrary third-party raster assets or logos.

No new icon asset, component, token, interaction or production dependency was added by this research. Any later application should be a scoped design task with matched before/after specimens, actual-size review and preservation of current scientific meanings and actions.


## Owner-requested field-mode replacement follow-up — 2026-11-03

The marked app-bar crescent is the Red field mode toggle, confirmed in [FieldModeButton](../../../lib/presentation/shared/field_mode_button.dart), not the Moon details action. The existing Settings copy says red on black preserves night vision; the button exposes toggled state and Turn on/off field mode labels. This distinction must survive any visual replacement.

Recommendation: trial [Lucide Eye](https://lucide.dev/icons/eye) with a visible **Field** label, keeping a minimum 48px target, matching the existing outline weight and explicit **Red field mode** accessible name. Eye alone is ambiguous (visibility/preview), so this is a labeled-control proposal rather than a proven universal symbol. Preserve a persistent non-color-only on/off indication. Keep Moon for the astronomical content and Tonight navigation. Do not use Eye-off for the off state: it suggests hiding content. [Scan-eye](https://lucide.dev/icons/scan-eye) adds scan/focus/biometric associations; [Eclipse](https://lucide.dev/icons/eclipse) remains close to light/dark theme and lunar-event meanings. These are design judgments informed by the official icon tags, not validated user-recognition results. No icon or gesture change has been applied to Figma or Flutter in this follow-up.


### Accepted local adoption — 2026-11-03

The owner approved the labeled Eye recommendation. Current After Tonight and Plan now use Eye over Field in the unchanged 48px target; On adds a check and neutral active surface. Geometry derives from the [official Lucide Eye SVG](https://github.com/lucide-icons/lucide/blob/main/icons/eye.svg), locally rendered at 20px with a 1.8-unit outline on its 24-unit viewBox. The local prototype toggles its indicator only. Astronomical Moon/root-navigation identities, shared catalog and Flutter remain unchanged. See the current [workflow](../WORKFLOW.md) for evidence and limitations; the preceding proposal text is historical.
