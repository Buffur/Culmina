   6  # Share
   7  
   8  Deploy the user's runnable prototype so they can share it with others.
   9  
  10  ## Critical Overrides
  11  
  12  - Refer to the Plugin router [$index](../index/SKILL.md) before proceeding.
  13  - Follow [$critical-overrides](../../references/critical-overrides.md).
  14  
  15  ## User Context
  16  
  17  Before starting, load [$user-context](../user-context/SKILL.md) and run its preflight script when local shell access is available.
  18  
  19  Use saved product URLs, Figma files, screenshots, reference images, codebase paths, Storybook, tokens, design systems, brand assets, component refs, browser preferences, and share targets as grounding material when relevant.
  20  
  21  Do not inspect every saved reference. Inspect only what the current task needs.
  22  
  23  ## Workflow
  24  
  25  1. Confirm the prototype directory and the user's preferred deployment target.
  26  2. If the user invokes Product Design with @Sites, @Vercel, or another deployment tool, treat that as the selected hosting target.
  27  3. If the user did not choose a target, ask one question:
  28  
  29  > Where should I deploy this: @Sites, @Vercel, or another target?
  30  
  31  4. Before using Sites for a fresh Product Design prototype, keep the existing project intact. Run `npm run build` and `npm run test:sites`; for `mobile-app`, run `npm run check:runtime` first. Confirm `dist/client/index.html`, `dist/server/index.js`, `dist/.openai/hosting.json`, and source `.openai/hosting.json` exist. Hand that verified project to `sites-hosting`. Do not invoke `sites-building`, run `init-site.sh`, or replace the Product Design runtime with a Vinext starter.
  32  5. Use the selected deployment tool when it is available.
  33  6. If the selected tool is not available, say that clearly and ask whether to use another target.
  34  7. Run the deployment when possible. Do not give setup instructions if you can complete the deployment directly.
  35  8. Return the shareable URL.
  36  9. State any misses or manual follow-up the user still needs to do.
  37  
  38  ## Rules
  39  
  40  - Do not deploy before the user chooses or confirms the target.
  41  - Do not claim the prototype is shared until you have a working URL.
  42  - If the selected tool is not available, say that clearly and ask whether to use another target.
