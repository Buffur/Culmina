   8  You're tasked with translating the visual target image into a high-quality, interactive website or web app.

  39  ## Workflow
  40  
  41  CRITICAL: THIS IS NOT GUIDANCE. THIS IS A CHECKLIST TO COMPLETE.
  42  
  43  1. Do not start unless you have a selected image, screenshot, mockup, or Image Gen result to recreate. A written brief is not enough.
  44  
  45  2. Resolve the exact selected visual target before building.
  46  
  47      - If the user selected a numbered `$ideate` option, use the Nth displayed generated-image result from the most recent ideation set. Do not use the original concept planning order or Image Gen prompt submission order.
  48      - Use the concept-name list from `$ideate` only when it was explicitly written in the same displayed-image order.
  49      - A generated-image result ID, selected image attachment, screenshot, mockup, or Figma frame is stronger than a bare ordinal. Prefer that exact reference when available.
  50      - If the selected result cannot be resolved unambiguously, stop before implementation and ask the user to name the concept or reattach/select the image. Never guess and build a nearby option.
  51  
  52      Mobile runtime exception: 1:1 fidelity applies only to app-owned content inside the device screen. `PhoneFrame`, `StatusBar`, `HomeIndicator`, `KeyboardDock`, and the device assets are template-owned infrastructure. Preserve them even if the reference omits them, depicts different device chrome, or includes chrome in the image. Never recreate device chrome as an image asset.
  53  
  54  3. Treat the resolved image as the design to recreate.
  55  
  56  4. If the provided design is a mobile viewport, build a mobile app. When creating a fresh local app for that case, use [local-prototype-preflight](../../references/local-prototype-preflight.md) with `--template mobile-app`. If it's unclear, default to desktop.
  57  
  58     Before planning or implementing with the `mobile-app` template, read its `AGENTS.md` and follow its runtime and component guidance.
  59  
  60  5. Review the reference design, catalog every image asset in the design, and use the Image Gen tool to create individual images for each one. Zoom in so you can catch every asset that needs to be generated.
  61  
  62      Examples include:
  63  
  64      - Hero images including full bleed image backgrounds
  65      - Featured article imagery
  66      - Thumbnails
  67      - Decorative illustrations
  68      - Textures and background motifs
  69      - Logos
  70      - Product images
  71      - Avatars
  72  
  73      Rules:
  74  
  75      - CRITICAL RULE: Do not create custom div art, CSS art, inline SVGs, handcrafted SVGs, HTML element drawings, div/span shapes, CSS drawings, gradients, emoji, or text glyphs instead of real icons and image assets ever. Use the built-in Image Gen tool for images and the closest matching icon library for icons.
  76      - If text is part of an image asset, keep it in the image asset. Examples include full bleed hero images, signs, posters, packaging, storefronts, article art, and illustrations where the type belongs to the visual itself. Do not crop the background image and recreate that text with transparent text boxes, HTML, CSS, or separate overlay layers unless the source clearly shows editable UI text sitting on top of the image.
  77      - Do not use generic placeholders where the reference implies custom visual content.
  78      - Generated assets must share the same art direction, palette, rendering style, and design language as the reference mockup.
  79      - The built-in Image Gen tool does not support transparent images; post-process generated assets when transparency is required.
  80      - For mobile prototypes, do not catalog or generate device bezels, notches, status bars, clocks, signal or battery indicators, or home indicators. The mobile runtime owns those elements.
  81  
  82  ### Parallel asset production
  83  
  84  After cataloging and measuring the reference assets, spawn up to three asset subagents while the main agent builds the app structure.
  85  
  86  Give each subagent one raster asset task at a time with its reference crop, exact dimensions, focal point, style, output path, and consuming component. Asset subagents generate, inspect, save, and report the asset path only. They must not edit source code, run the browser, or deploy.
  87  
  88  Prioritize critical above-the-fold assets first, then reuse agents for supporting assets. Do not delegate standard UI icons or supplied brand logos.
  89  
  90  6. Define all sections of the page. For each section, meticulously measure the layout, spacing between elements, and the size and space of the elements themselves.
  91  
  92  7. Find freely available fonts that match the target design.
  93  
  94  8. Find a freely available icon library that matches the target design. Do not default to Lucide icons. Search for the best match.
  95  
  96      Rules:
  97  
  98      - CRITICAL RULE: Do not create custom inline SVGs, handcrafted SVGs, HTML element drawings, div/span shapes, CSS drawings, gradients, emoji, or text glyphs. Use the built-in Image Gen tool to generate assets and use the closest matching icon library for icons.
  99  
 100  9. Build the app starting with [local-prototype-preflight](../../references/local-prototype-preflight.md). Unless the user asks for a static mock, full production behavior, or a different scope, bring the app or website to life with:
 101  
 102      - Working navigation, links, tabs, menus, and primary CTAs.
 103      - Functional inputs, filters, toggles, selections, and forms shown in the main experience.
 104      - Visible UI states: hover, focus, selected, open/closed, loading, empty, and success where relevant.
 105      - The main task, conversion path, or user journey working from start to finish when the product has one.
 106  
 107      Controls outside the core experience may be visual-only. Do not build auth, persistence, backend/API calls, integrations, or exhaustive edge cases unless requested.
 108  
 109      Rules:
 110  
 111      - Place every image asset you generated into its position before proceeding. I repeat, replace all placeholders, including CSS/SVG placeholders, before proceeding.
 112      - Do not leave controls in the core experience as static chrome. Do not create new pages or routes unless the user asks for them.
 113  
 114  10. Run the local app.
 115  
 116  11. Capture the local app using the Browser Choice rule in [$index](../index/SKILL.md#browser-choice).
 117  
 118  12. Run [design-qa](../design-qa/SKILL.md) as the blocking build gate.
 119  
 120      Steps:
 121

 123      - Compare the same viewport and the same interaction state. If they do not match, capture the missing view first.
 124      - Save the QA report as `design-qa.md` in the project root.
 125      - Fix P0/P1/P2 issues, capture the app again, and repeat until the QA report says `final result: passed`.
 126      - Do not keep looping on P3 polish. Include any remaining P3s as follow-up iteration notes.
 127      - If source capture, prototype capture, or visual comparison is blocked, stop. `design-qa.md` must say `final result: blocked`.
 128      - Do not hand off unless `design-qa.md` exists and says `final result: passed`.

 134      - Keep the local preview open for the user. In ChatGPT Work Mode, tell the user to inspect the prototype in the cloud browser; do not provide a clickable local URL. In Codex Desktop, provide the clickable local URL. Do not deploy to Sites unless the user explicitly asks to share, publish, or deploy.
 135      - After the preview handoff, use the shared build handoff from `critical-overrides.md`. Do not add a different completion message.
