12 /// "Ljubljana ▾ Fri, Nov 14 ▾" (S5.6; ADR-019 §5, §6; addendum §3.1–§3.2):
13 /// the one control that says which site and night a screen describes, for
14 /// Tonight and the planner. Each part is its own 48 dp target that reports
15 /// a tap; what choosing does (the site picker, or changing the plan's
16 /// night, UX-11) is the adopting screen's (P6.3, P6.6).
17 ///
18 /// Below it, once, the zone rule (trap 2): times are in the site's zone, or
19 /// labelled as the device zone when the site has none. Without a site there
20 /// is no night (ADR-007 §9), so only the site part shows.

22 /// S6.16: [framed] sets it on a card, so the site and night read as one
23 /// deliberate context area (Tonight and the planner); each part leads with

234 /// The shared night picker (S5.6): the date picker in the app's theme (red
235 /// in field mode), from a year ago to five years ahead as the planner's
236 /// picker allows, starting at [initial] (else [today]). Returns the chosen
237 /// evening, or null when cancelled.
238 Future<CalendarDate?> pickNight(
239 BuildContext context, {
240 CalendarDate? initial,
241 DateTime? today,
242 TransitionBuilder? builder,
243 }) async {
244 final now = today ?? DateTime.now();
245 final picked = await showDialog<DateTime>(
246 context: context,
247 builder: (context) {
248 final dialog = NightPickerDialog(
249 initialDate: initial == null
250 ? DateUtils.dateOnly(now)
251 : DateTime(initial.year, initial.month, initial.day),
252 firstDate: DateTime(now.year - 1, now.month, now.day),
253 lastDate: DateTime(now.year + 5, now.month, now.day),
254 );
255 return builder?.call(context, dialog) ?? dialog;
256 },
257 );
258 return picked == null ? null : CalendarDate.fromDateTimeFields(picked);
259 }
