## One iteration = one screen

Historical procedure title retained for existing links. The owner superseded per-screen approval on2026-11-05 with the current pipeline rule below; steps1–6 still apply to each screen.

1. **Establish the source.** Read the current router, screen owner/caller and source-backed capture/fixture. Inspect the complete matching BEFORE and map its meaningful blocks, visualizations, information coverage and actions to After using the [functional-preservation rule](rules_and_constraints.md#functional-preservation--owner-correction-2026-11-05). Dated captures are not current runtime proof. Record what is known, missing or different before authoring. Source/product facts override illustrative DS fixture text; a responsive fallback alone does not justify losing a BEFORE capability. Ask the owner about doubtful equivalence before committing that tradeoff.
2. **Select a populated base fixture.** Choose one actual date/site/entity/record consistent with its entry context. Base means one main composition; it does not permit replacing truthful Unknown, unrecorded or cached/provenance facts with fabricated measurements. No personal records are edited to prepare a fixture.
3. **Map content to canonical roles.** List the chosen masters, slots and text properties before drawing. Use current parent/nested/field/value roles and light positive/commit actions. Reuse matched accepted patterns; keep scientific geometry and plain explanations distinct from decorative cards.
4. **Resolve a real component gap centrally.** If an existing master fits, configure an instance. If the screen introduces a genuine reusable pattern, add one source-backed default recipe to DS and its index, then use its instance. Do not detach instances or add local colors/type scales to bypass the contract. Stop for an owner decision if the missing pattern requires a new visual direction or changed product meaning. Apply the [UX exploration extension](#ux-exploration--structural-alternatives-extension-of-step-4-gate) when the owner questions an existing block's role.
5. **Build one base frame per numbered screen.** Use a375px-wide Hug-content Longread and complete source wording by default. Apply an explicitly owner-approved viewport exception recorded in REDESIGN_RUN, including the2026-11-06 scrolling catalogues6/8/24/27 and fixed Apply8. Retain complete ordered data and relevant chrome/actions. No unrequested second presentation, extra empty/loading/error/offline/edge-case screen, modal substate or hidden alternate screen. Other fixed-footer/safe-inset work remains separate until authorized and measured.
6. **Check the result.** Verify data/units/time/provenance and action/persistence semantics; canonical links and default properties; readable wrapping, target bounds, spacing and no overlap; full visual content at 100%; scoped Preview and any implemented route/Back link. When a shared master changes, re-export both accepted anchors and the redesign copies before accepting that change. Do not claim native/accessibility/200% proof from a Figma render.
7. **Deliver and stop.** Report the Figma link, exact component owners, source fixture, actual checks and remaining limits. End the delivery with the shared [Mandatory Delivery Audit](../../AGENTS.md#mandatory-delivery-audit-step-7-control), retaining its exact four labels and honest decision/assumption disclosures. Keep one full-scale PNG and review screenshot. For an authorized pipeline batch, deliver after all batch entries are built and batch QA has run; no intermediate owner approval is needed. Outside an authorized batch, wait for the next owner instruction. Corrections stay within the current screen and affected canonical owners.

## UX Exploration & Structural Alternatives (Extension of Step 4 Gate)

Owner rule, 2026-11-05:

- **Trigger:** When the owner questions whether a source/BEFORE block, tab or section is needed, including evaluation of removal, merging, duplication or UX alternatives.
- **Gate — propose before Figma edit:** Treat structural removal or merging as changed product meaning under Step 4. Pause Figma building for that screen.
- **Required output:** Present 2–3 distinct UX options, such as keep/compact, merge into an existing block or remove, with explicit trade-offs against source/BEFORE data completeness. Wait for the owner's selection before generating or revising the frame. Once the owner selects an option, execute that selection without asking for the same approval again.
- **Exception:** Normal UI/UX QA requests about spacing, hierarchy, typography or sizing do not trigger this pause; execute those corrections directly.
